## 一键设置总满分·"只更新总满分分项不动"排查与修复(11:32,主理人直改,未 commit)
- **现象证实**:真实库 id41(分项全0/总满分20,updated 09-18 08:41)与 id48(分项全0/总满分10,updated 09-17 22:05)是"只写总满分"的精确形态;但两次写入都发生在 09-18 09:27 五科版(六列 UPDATE)上线**之前**——现行 apply 是六列同事务写,今早 09:44:27 的 id40/id42 六列写入证明运行服务已是新版,现行写路径无 bug。
- **根因**:旧版历史数据(只写 total_full 一列)留下的不一致行,被现行守卫 `total_full > 0 → 跳过` 永久锁死——preview 不列出、apply 拒绝修复,"一键设置总满分"对这些行永远不可用,列表症状持续存在。
- **修复**:守卫口径从「总满分单列判 0」切换为「五分项全 0 才算未配置」。preview WHERE 改五列 AND=0;apply 拦截改 FIELDS.some(col>0);跳过原因文案改"五科分项已有配置(>0),不覆盖"。历史遗留行(分项全0、总满分>0)现可被列出(currentTotal 保留历史值可见)并六列重写修复。前端弹框三处文案同步(alert/空列表提示/底部汇总)。

- 教训:**守卫条件的语义要与写入粒度匹配**——写入从单列升级为六列后,"未配置"的判据也必须从单列升级为六列口径,否则升级前产生的中间态数据会被新守卫永久排除,形成"既修不了又看不见"的死角。
