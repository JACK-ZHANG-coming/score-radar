# 试卷批次管理 · 增量 PRD

> 文档性质：增量需求文档（在现有 score-radar 成绩管理系统上新增「试卷批次管理」页面）
> 唯一需求来源：team-lead 转述的用户原始需求九节 + 4 条澄清约定
> 语言：简体中文
> 技术栈约束：前端 Vue 3 `<script setup>` + Element Plus（沿用现有版本）；后端 Express + better-sqlite3 + JWT（沿用）；不新建测试框架，验证走 API 级 + 构建级

---

## 一、项目目标

为每一套「试卷批次」维护基础配置（总满分、各题型分项满分、合格占比），并让学生成绩记录页面能够：

1. 在下拉框中选择已维护的试卷批号，**自动带出该套卷子的满分配置**；
2. 在**导入成绩 / 新增单条成绩**时，按批号配置做分数合法性校验（分项得分不超分项满分、总分不超试卷总满分）；
3. 按 `合格线 = 试卷总满分 × 合格占比 / 100` **自动计算并展示合格/不合格状态**。

从而把原先散落在 `scores.batch_no` 文本字段里的「试卷批号」升级为**可配置、可复用的主数据**，打通「试卷批次管理」与「学生成绩记录」两个页面的数据联动，实现成绩校验与合格判定的标准化、自动化。

**范围边界（本 PRD 覆盖）**：新增独立页面「试卷批次管理」、新增后端 `paper_batches` 表与一组接口、改造现有成绩页下拉数据源与导入/新增链路以支持配置带出与分数校验。**不覆盖**：学生信息模块改动、登录/权限体系改动、既有成绩字段（含二次订正分、备注）语义变更。

路由 `/paperBatch`，左侧导航与【学生成绩记录】【学生信息管理】同级，顺序：学生成绩记录 → 试卷批次管理 → 学生信息管理。

│ 区1 顶部搜索筛选区                                            │
│   试卷批次名称[输入框 模糊]  试卷批号[输入框 模糊/精确]       │
│   [查询]  [重置]                                             │
├─────────────────────────────────────────────────────────────┤
│ 区2 操作按钮栏                                               │
│   [+ 新增试卷批次](primary) [导入](success) [下载导入模板]   │
│   [批量删除](danger, 带数量, 无选中禁用)      [导出]         │
├─────────────────────────────────────────────────────────────┤
│ 区3 表格数据列表（多选框 + 列设置 + 排序 + 分页）            │
│   | 选择 | 序号 | 试卷批号 | 试卷批次名称 | 选择题满分 | ... │
│   | 试卷总满分 | 默认合格占比 | 计算得出合格线 | 备注 |      │
│   | 创建时间 | 操作(编辑/删除) |                             │
│   └── 分页（10/25/50/100/500，默认 25，越界钳制）          │
├─────────────────────────────────────────────────────────────┤
│ 弹窗：新增/编辑试卷批次（核心表单）                         │

| python_full | REAL | 是 | 0 | Python 满分 ≥0（澄清1 必填） |

| 5 | 电子表格满分 | 数字输入 | ≥0（澄清1 必填，可 0） |
| 6 | Access满分 | 数字输入 | ≥0（澄清1 必填，可 0） |
| 7 | Python满分 | 数字输入 | ≥0（澄清1 必填，可 0） |
| 8 | 综合题满分 | 数字输入 | ≥0（澄清1 必填，可 0） |

**5 条提交校验逻辑（前端 + 后端双重校验）**

| 序号 | 规则 | 不满足时提示 |
| --- | --- | --- |

| ② | 所有题型分数 ≥ 0 | 「分数不能为负数」 |

| ④ | 合格占比在 0~100 之间 | 「合格占比需在 0~100 之间」 |
| ⑤ | 试卷批号不重复（新增时） | 409 `duplicate`（弹确认/提示） |

## 五、接口契约表

> 基准：沿用 `server/src/routes/scores.js` 的响应结构 `{ code:0, data:{...} }`、错误用 HTTP 状态码 + `{ code, message, data }`、`authRequired` 鉴权中间件。
> 分页参数与成绩页一致：`page` 默认 1、`pageSize` 默认 25、上限 500、越界钳制、响应含 `totalPages`。

### 新增接口（路由前缀 `/api/paper-batches`）

| # | 方法/路径 | 入参 | 出参 | 校验/备注 |
| --- | --- | --- | --- | --- |
| 1 | `GET /api/paper-batches` | `name`(模糊),`batchNo`(模糊),`page`,`pageSize`,`sortField`,`sortOrder` | `{list,total,page,pageSize,totalPages}`，list 含派生 `passLine` | 分页+筛选+排序 |
| 2 | `POST /api/paper-batches` | body: `batch_no,batch_name,choice_full,spreadsheet_full,access_full,python_full,composite_full,total_full,pass_ratio,remark` | 创建行 / `409 duplicate` | ⑤批号唯一；①②③④；`passLine=ROUND(...)` |
| 3 | `PUT /api/paper-batches/:id` | body 同上（含 `batch_no`） | 更新行 / `404` / `409 duplicate` | 排除自身查重 |
| 4 | `DELETE /api/paper-batches/:id` | path `id` | 删除成功 / `404` / `409` | 关联成绩存在→`409`「该试卷批次下存在学生成绩，无法删除，请先删除关联成绩数据！」 |
| 5 | `DELETE /api/paper-batches/batch` | body `{ids:number[]}` | `{deleted}` / `400` / `409` | 注册在 `:id` 之前；任一关联成绩→整体 `409`（见 Q6） |
| 6 | `POST /api/paper-batches/import` | `multipart file`(+可选 `batchNo`) | `{inserted,updated,errors[]}` / `409` | 批号重复/分数非法→错误行提示；复用 excel.js |
| 7 | `GET /api/paper-batches/export` | 同查询筛选参数（不含分页） | `application/vnd.openxmlformats...` xlsx | 导出**当前筛选全集** |
| 8 | `GET /api/paper-batches/by-no/:batchNo` | path `batchNo` | `{batchNo,totalFull,choiceFull,spreadsheetFull,accessFull,pythonFull,compositeFull,passRatio,passLine}` / `404` | 成绩页联动取配置用（见第六章） |

### 改造现有接口（成绩侧）

| # | 方法/路径 | 改造点 | 说明 |
| --- | --- | --- | --- |
| 9 | `GET /api/scores/batch-nos?class=`（现有） | 返回集合 = `DISTINCT scores.batch_no`（按 class 过滤）**∪** `DISTINCT paper_batches.batch_no`（全量） | 澄清4：合并去重；`paper_batches` 无 class 列，批号全量纳入（见 Q7） |
| 10 | `POST /api/scores`（现有） | 写入后调用 `ensurePaperBatch(batch_no)` 静默补占位行 | 澄清3 / P0-13 |
| 11 | `POST /api/scores/import`（现有） | 逐行写入后 `ensurePaperBatch(batch_no)`；并按批号配置做分数校验（见第六章） | 澄清3 + P0-9 |

> `ensurePaperBatch(batch_no)`：若 `batch_no` 不在 `paper_batches` 则插入占位行（`*_full=0, total_full=0, pass_ratio=60, created_at=派生/当天`）。建议封装为 `server/src/utils` 或 routes 内 helper，成绩导入事务内调用。

## 六、成绩页联动规则（重点）

### 6.1 配置带出（八.1 / 接口 8、9）

1. 成绩页「试卷批号」下拉数据源改为接口 9（合并后集合），保留班级级联。
2. 用户在下拉选择某批号后，前端调用 `GET /api/paper-batches/by-no/:batchNo` 取该批号配置（总满分、选择题满分、电子表格满分等），缓存到当前表单/导入上下文，用于即时提示与校验。

### 6.2 分数校验（八.2 / P0-9）

在**导入成绩**与**新增单条成绩**提交时，按所选批号配置校验（仅当该批号在 `paper_batches` 中存在且 `total_full>0` 即「已配置」时生效；占位批号 `full=0` 的处理见 Q2）：

| 校验项 | 规则 |
| --- | --- |
| 选择题得分 | `≤` 该批号 `choice_full` |
| 电子表格得分 | `≤` 该批号 `spreadsheet_full` |
| 总分 | `选择题+电子表格+Access+Python+综合题 ≤` 该批号 `total_full` |
| 不满足时 | 提示「第 N 行分数非法（超出试卷满分配置）」，该行跳过/导入失败（见 Q2/Q3） |

### 6.3 合格状态自动标记（八.3 / P0-10）

- 合格线 `passLine = ROUND(total_full * pass_ratio / 100, 2)`（澄清2）。
- 学生记录判定：`学生总分 ≥ passLine` → 合格（绿色）/ 否则 不合格（红色）。
- 「学生总分」取数口径见 Q4（建议取 `scores.total` 总成绩列，与现有列表着色一致）。
- 列表「考试状态/合格」展示：在成绩列表新增合格状态标签（或复用现有 `status` 标签区），不改动既有 `status` 字段语义。

| 场景 | 处理 |
| --- | --- |
| 删除已关联成绩的批号 | `409` 提示「该试卷批次下存在学生成绩，无法删除，请先删除关联成绩数据！」，不执行删除（P0-11） |
| 新增/导入批号重复 | 新增→`409 duplicate` 弹提示；导入→预扫描统计冲突行，`409` 带 `conflictCount`，前端一次确认覆盖/取消（P0-12） |
| 分项之和 ≠ 总满分 | 提交拦截，提示「分项分数总和和总满分不一致，请核对！」（规则③） |
| 合格占比越界 | 拦截，提示需在 0~100（规则④） |
| 分数为负数 | 拦截（规则②） |
| 分数小数位 | 最多保留 2 位小数（P1-4） |
| 成绩页出现新批号 | 静默补 `paper_batches` 占位行（分项 0/总 0/占比 60），批次管理页可见可补全（澄清3） |
| 下拉数据源 | `paper_batches ∪ scores` 去重合并，保留班级级联（澄清4） |
| 导入 Excel 解析 | 复用 `excel.js` 的 GBK 修复 + 表头校验（`missingHeaders`）+ 时间规范化；缺必需列→`400`（P2-1） |
| 创建时间派生 | 取该批号下 `submit_time` 出现最多的日期（众数），格式 YYYY-MM-DD；无成绩则取当天（P1-7） |
| 分页越界 | `page` 钳制到 `[1, totalPages]`，响应含 `totalPages`（沿用成绩页逻辑） |
| 批量删除空/无效 | 空数组或非数组→`400`「请先选择要删除的记录」；无效 ID→`400`（沿用成绩页逻辑） |
